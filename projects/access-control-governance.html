Access Control Policy, Standard and Exception

Rewrote an untestable 2021 policy into a policy plus measurable standard, set decision rights with a RACI, and decided an exception for an unsupported server in PCI scope.

NIST SP 800-63BPCI DSS v4.0.1ISO/IEC 27001:2022

Skills shown

  • Policy writing
  • Governance design
  • Exception management

Artifacts

  • Lab workbook (T_RACI, T_PolicyReview, T_Exception)

The situation

Larkspur's access policy said passwords change every 30 days, IT reviews access "periodically", and remote access goes through a VPN the company no longer owns. Separately, engineering asked for a 12-month patching exception for a Windows Server 2012 R2 box that reconciles card settlements.

Approach

  1. Scored each legacy line: testable, current, owned.
  2. Separated policy (what and why) from standard (numbers) and procedure (tool steps).
  3. Reconciled NIST SP 800-63B (no forced rotation) with PCI DSS 8.3.9 (90-day rotation when a password is the only factor).
  4. Built a RACI with one Accountable per activity and tested it against who would really sign.
  5. Assessed the exception: support status, PCI scope, compensating controls, duration, approver.

Analysis

Legacy lineProblemRewrite
Change passwords every 30 daysContradicts current NIST guidanceMFA everywhere; 12+ character minimum; no forced rotation
IT will review access periodicallyUntestable; wrong ownerSystem owners review High systems every 90 days, others every 180
Users should not share accounts where possibleUntestableShared accounts prohibited unless registered as an exception
Use the Barracuda VPNTool retiredTool names moved to procedures

Findings

  • Requiring MFA everywhere removes PCI 8.3.9's rotation rule, so both sources are satisfied.
  • The exception server lost all security updates in October 2026 and handles card data, so it needs a QSA-reviewed compensating control.
  • Risk acceptance belongs to the business owner (CTO), not the CISO.

Recommendations

  • Approve the exception for 90 days, not 12 months, conditional on dated migration milestones.
  • Compensating controls: isolated segment, no internet, allowlisting, EDR and alerts on new outbound connections.
